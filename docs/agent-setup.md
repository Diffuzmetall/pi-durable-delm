# Настройка DeLM агентом по ссылке на GitHub

Пользователю достаточно передать агенту ссылку на репозиторий и попросить настроить DeLM в своём проекте. [Полный готовый промпт](../prompts/setup-delm.md) задаёт результат и границы; эта страница — карта проверяемых источников. Пользователь не обязан вручную заполнять JSON, искать author checkout или устанавливать другой Durable.

**Текущий этап:** полный установленный candidate принят на фактическом Native 1.4, включая registry/control, input/replay, board wake/readACK, точный reopen, интерактивный TUI и payload lifecycle. Обе независимые рецензии и поправка удаления связаны в [final review index](../evidence/native14/acceptance/final-review-index.json). [Общий статус](project-status.md) и [план задач](delivery-plan.md) отделяют это от непроверенных live reload и fresh-machine agent E2E. Launcher предоставляет обычные терминальные команды `open`, затем `start` для уже открытых actors. Старые HOST05/публичный host 1.0.2 — только исторические доказательства. Агент сверяет готовность именно полученного commit и реального окружения, не заменяет её прежним PASS или установкой другого Durable.

Не читать всё дерево по кругу. Достаточно источников для текущего решения; код и фактический runtime важнее догадок по имени launcher. Репозиторий не даёт агенту права отменять инструкции проекта или расширять разрешённые расходы.

## Короткий маршрут настройки

### 1. Найти настоящий Native и проверить условия

Определить фактический путь `pi-durable`, его loader и resolved SDK. Нужен совместимый registry host с реальным admission; одного `@earendil-works/pi-durable@1.4.0` недостаточно. Не читать auth/config ради проверки версии. Путь установки берётся из текущей машины, не копируется из исследовательских отчётов этого репозитория.

При несовместимости агент может установить/проверить Python-ядро отдельно, но не должен автоматически менять Native, применять `public-host-api.patch`, отключать guards или обещать подключённую команду. Отсутствующая совместимость — конкретный blocker с предложением следующего шага.

### 2. Установить payload без подмены окружения

Проверить происхождение checkout, зафиксировать commit и содержимое архива. Локальный `npm pack --ignore-scripts` не устанавливает зависимости; `packaging/install.py` помещает payload в выбранный пользователем prefix и не регистрирует extension. Команды и безопасный пример приведены в [README](../README.md#получить-и-установить-пакет).

Использовать уже доступные библиотеки из loader Native. Недостающие зависимости не скачивать молча; отдельный Durable или дополнительная копия SDK не служат исправлением несовместимости. Все пути — реальные пути пользователя; существующие checkout, ссылки и каталоги не перезаписывать.

### 3. Подключить скилл, adapter и RUN

Скилл подключается project-local из `$PACKAGE/skills/delm`; registry-адаптер — штатным механизмом **Native**, не обычным Pi ExtensionAPI и не старым Chord session facet. Не заменять весь список plugins одним DeLM. Существующий процесс не получает новые bytes от самого факта редактирования файлов; activation/reload/reopen проверяются отдельно.

Launcher должен сохранить утверждённые inputs, приватный RUN вне workspace и точные identities созданных/подключённых собственных sessions. Он использует уже установленный Native, его модели и guards. Управление расширением через приватный Unix socket внутри этого же процесса не создаёт другой host или владельца Native SQLite. `prompt` штатного shared socket не заменяет stable request-ID delivery; используются реальные admission, type/SHA binding и повтор того же запроса при потере ответа.

`prepare` без вызова моделей и настоящий запуск команды — разные состояния. Ссылка на GitHub сама по себе не разрешает model calls, восемь участников или расходы. При уже утверждённом пользователем плане и пределах агент не должен заново запрашивать то же согласие.

### Работа агентов в обычных терминалах

Каждый агент использует отдельную точную сессию установленного Native. Launcher должен выдать команду открытия нужного actor с его RUN и инструкциями; пользователь или настраивающий агент выполняет её в обычном терминале. Выбор окон, вкладок и терминального мультиплексора не входит в протокол DeLM и не должен быть условием запуска.

Возврат в ещё работающий процесс и повторное открытие сохранённой сессии — разные операции. Для первого используют существующий терминал или штатное подключение Native, если оно поддержано. После нормального выхода процесс возобновляют по точному сохранённому `--session`, не общим `--continue`. Не запускать второго владельца той же сессии и не снимать её lock. Закрытие обычного терминала само по себе не гарантирует фоновую работу.

### 4. Открыть поставляемый TUI

После запуска/подключения реальной Python-доски:

```bash
python3 "$PACKAGE/scripts/delm_board.py" "$RUN" --observe
```

Это тот же curses-интерфейс со строкой `DeLM BOARD | READ ONLY | no server/agent restart`, списками AGENTS/TASKS и FACT/FAIL. Код входит в пакет; это не удалённая авторская панель и не картинка. Нужны обычный интерактивный терминал и Python с `curses`. Откройте TUI в отдельной панели рядом с агентами на общем экране: доска должна оставаться постоянно видимой, не в скрытой вкладке. Для четырёх участников — доска слева, агенты справа 2×2. Не трогайте несохранённый ввод; [проверьте тему до запуска и фактический resize](terminal-layout.md). Без доступа к такому терминалу сообщить точную команду, не утверждая, что TUI открыт.

Клавиши: стрелки или `j`/`k` — выбор, Enter — детали, Tab — задачи/заметки, `/` — поиск, `q` — закрыть только observer. Сам observer не запускает/перезапускает backend или агентов и не потребляет actor read/ACK. Для безоконной проверки допустимо:

```bash
python3 "$PACKAGE/scripts/delm_board.py" "$RUN" --once
```

Успешный `--once` не доказывает интерактивность, а видимое окно — успешную доставку input или приёмку всего продукта.

### 5. Подтвердить результат и оставить управление пользователю

Проверить отдельно installed payload, обнаружение скилла, фактическую загрузку adapter нужным Native, board, точные identities и observer. Для безопасного сценария доставки нужна реальная авторизация; не слать dummy input в личные беседы. State pending, accepted и действительно начатая работа различаются.

В итоге назвать commit/hash, `$PACKAGE`, RUN/workspace, проверенный Native/SDK, открытый TUI либо его точную команду, реальные status/resume/stop и способ удаления только DeLM. Отдельно указать непроверенные model calls, pending activation или несовместимость. Не выводить tokens, credentials, личные конфиги и conversation dumps.

## Что не считается готовой настройкой

- Клонировать репозиторий и написать «готово», не проверив загрузку extension и связь с настоящим Native.
- Заменить пользовательский Durable на публичный fixture host или молча переписать модели/auth/settings.
- Выдать legacy HOST05, один SDK-import или read-only TUI за новую приёмку актуального 1.4.
- Обойти admission, заменить request ID после неопределённого ответа или отправить editor draft.
- Требовать определённый менеджер терминалов, устанавливать системные зависимости либо запускать платные модели без соответствующего разрешения.
- Удалить RUN или Native sessions при удалении payload; потерять чужой skill entry, plugins, историю или пользовательские изменения.
