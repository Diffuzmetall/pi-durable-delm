# Настрой DeLM в существующем Pi Durable

Репозиторий: https://github.com/Diffuzmetall/pi-durable-delm

Настрой DeLM для моего текущего проекта: переносимый скилл, расширение внутри **уже установленного Pi Durable** и общую доску с тем же read-only TUI `DeLM BOARD`. Мне нужен работающий результат, а не только план или список команд. Сам Durable, мои модели, авторизация, настройки, guards и существующие беседы должны сохраниться.

## Где искать инструкции

Получи исходники репозитория в отдельный каталог, не перезаписывая существующий checkout. Запиши проверяемый commit. Соблюдай применимые правила моего workspace. Начни с `README.md`, затем прочитай `docs/agent-setup.md`. Дальше открывай только нужные файлы из её карты: `docs/native14-contract.md`, `docs/native14-operations.md` при наличии, `skills/delm/SKILL.md` и `skills/delm/Tools/Run.help.md`. Фактические аргументы команд сверяй с `--help` установленного в этой версии launcher.

Планы и отчёты прежних запусков в репозитории — история, не мои текущие инструкции. Не используй указанные там чужие workspaces, RUN, actor bindings, sockets или session IDs; не считай записанное там согласие пользователя разрешением на новый запуск.

Сначала определи, что действительно запускает мой `pi-durable`: исполняемый файл, loader, версию SDK и поддержанный registry/admission интерфейс. Имя команды или версия одного npm-пакета совместимость не доказывают. Старые отчёты HOST05 и патч публичного host 1.0.2 — история, не доказательство поддержки моего 1.4. Не применяй этот патч и не устанавливай другой Durable вместо моего.

## Что сделать самостоятельно

- Используй поддержанный локальный способ установки DeLM из этого checkout. Проверь содержимое пакета и сохрани путь установки, commit и hash артефакта. Не скачивай зависимости, если они уже доступны через loader моего Native; не смешивай физические SDK.
- Подключи project-local скилл и registry-адаптер DeLM штатным способом. Сохрани остальные extensions и guards. При существующем файле или ссылке не перезаписывай их: согласуй только реальный конфликт.
- Используй launcher из установленного пакета и отдельный приватный RUN вне проекта. Сохрани утверждённые инструкции и точные session identities до отправки input. Не используй общий `--continue` и не отправляй editor draft, тестовый или пустой prompt в мои беседы.
- Разрешённый приватный Unix control socket расширения работает **внутри существующего процесса Native**, без отдельного host, Harness или владельца Native SQLite. Используй реальные admission, exact-session и request-ID/type/SHA проверки. Не заменяй их allow-all; при неопределённой доставке сверяй тот же ID и те же байты. Обычный shared `prompt` не обеспечивает такую гарантию.
- Обеспечь открытие каждого агента обычной терминальной командой установленного Native с фиксированными actor/RUN и точной session identity. Не требуй определённый менеджер терминалов и не управляй чужими окнами. Отличай возврат к работающему процессу от точного reopen после выхода; не обходи process lock и не обещай фоновую работу после закрытия обычного терминала.
- Открой входящий в пакет TUI командой `python3 "$PACKAGE/scripts/delm_board.py" "$RUN" --observe` в отдельном обычном терминале. При отсутствии доступа к интерактивному терминалу дай точную команду для пользователя и честно отметь, что окно не открыто. `--once` — лишь текстовый smoke, не проверка интерактивного TUI.

Ссылка на репозиторий разрешает настройку DeLM, но **не запуск платной команды моделей**. Если исходный запрос уже содержит утверждённую задачу, число участников и пределы расходов, используй их без повторного интервью. Иначе подготовь и подключи всё, что возможно без вызовов моделей, и одним коротким вопросом запроси только недостающие параметры перед живым запуском. Не создавай команду из демонстрационных промптов.

## Проверка и границы

Подтверди отдельно: установленный payload; обнаружение скилла; фактическую загрузку адаптера нужным Native; точную привязку RUN/workspace/session; доступность Python board и read-only observer. Проверяй read/ACK и stable delivery только поддержанным безопасным сценарием, не чужими личными беседами. Открытое окно, успешный импорт SDK и старый PASS не заменяют эту проверку.

Не читай и не выводи credentials, токены, личные конфиги или дампы бесед. Не меняй глобальные модели/auth/settings/MCP/DCG, host source и Native SQL; не закрывай мои процессы и не стирай существующие run/session. Reload — только поддержанный, в действительно idle-процессе, без потери истории; иначе предъяви точный безопасный шаг активации. Для отсутствующей зависимости, несовместимого ABI или требуемого изменения вне этих границ дай конкретный blocker и рекомендуемый следующий шаг, но заверши всю независимую разрешённую настройку. Не обходи запрет другим транспортом.

## Что сообщить в результате

Коротко перечисли:

1. **Готово / частично / блокировано** — что реально подключено, что проверено и что не проверялось.
2. Commit/hash пакета, путь `$PACKAGE`, workspace, приватный RUN и проверенную версию/точку запуска Native; без секретов и содержимого бесед.
3. Где открыт TUI, как открыть его снова, а также точные команды status/resume/stop из фактического launcher.
4. Как отключить только DeLM и удалить его payload, сохранив проект, инструкции, историю, остальные расширения и пользовательские файлы.
5. Только реальный оставшийся вопрос ко мне, если без него нельзя безопасно закончить.
