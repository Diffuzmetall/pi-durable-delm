# TaskPlanning

Use useful outputs rather than numbers of files. For a CSV import request, a usable schema/parser contract can finish before backend and preview consumers; integration follows their verified outputs. Select 2/4/8 by genuinely parallel safe streams, not the final task count. Existing finished outputs and current owners prevent duplicate work.

A task records output, available inputs, producer, interface, source boundary, criteria mapped to the original request and real dependency IDs. Coupled paths have one writer. A parent groups scope and gates on its outputs, not a supervisor model; no child can depend on completion of a parent that waits for that child. Split preserves every parent criterion and checks deps plus output edges for cycles. Split retains the parent claim; its owner must checkpoint/release before claiming a child.

An early usable contract deserves its own DONE, not a FACT pretending to complete the producer's entire implementation. Relevant FAIL remains until explicit authorized correction/resolution; independent streams continue. Self-verification is inside the owned output, independent checks at a major milestone use existing peers rather than new reviewer models.
